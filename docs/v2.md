## Metadata persistence

### Question

What storage model is appropriate for video metadata?

### Candidates

- Relational database
- Document database
- Hybrid relational + JSON metadata

### Requirements

- Persistent metadata
- Efficient lookup by video ID
- Content hash lookup for deduplication
- Querying by creation date
- Querying by content type
- Consistency between video state and metadata
- Support for future media-processing metadata

### Decision

The metadata layer will use PostgreSQL with a relational schema
and JSONB for extensible video metadata.

Structured fields such as identity, storage location, content type,
size and lifecycle state will remain relational.

Media-specific metadata whose structure may evolve over time will
be stored as JSONB.

This avoids coupling the video model to a rigid schema while
preserving relational constraints and efficient indexing for
core application data.
